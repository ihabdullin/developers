# Личный amoCRM: локальная интеграция чтения и записи

## Виджет «Рекомендатель»

MVP для карточки сделки находится в [widget/](widget/README.md): поиск существующих
контактов, выбор и сохранение Contact ID, отображение актуального имени со ссылкой.
В README виджета описаны проверенные поля аккаунта, сборка ZIP, установка, тесты и обновление.
Локальный OAuth-клиент сохранён; frontend использует сессию пользователя amoCRM без секретов.
Наличие собранного ZIP не означает, что виджет уже установлен в аккаунте.

Отдельный проект на Mac. Не использует инфраструктуру, файлы или учётные данные СПЕКТР.
Python 3.9+; сторонних пакетов нет. Проверенное окружение 23.09.2026: macOS 26.5.2,
системный Python 3.9.6. Для длительной эксплуатации стоит перейти на поддерживаемый Python.

## Статус

Реализованы OAuth code exchange, refresh с ротацией пары токенов, автоматическое обновление,
клиент API v4, чтение сделок, контактов, компаний, задач, воронок и статусов.
Проверено на личном аккаунте https://infomedaccountru.amocrm.ru 23.09.2026:
OAuth выполнен; чтение первых 50 сделок, контактов, компаний и задач успешно;
получено 8 воронок и 57 статусов. Все запросы вернули HTTP 200.
Реальный refresh выполнен успешно, новая пара токенов сохранена.
Автоматическое обновление по истечении/401 проверено локальными тестами с имитацией API.
Добавлены создание и изменение одной сделки, контакта, компании или задачи за запрос.
Локальный агент может вызывать CLI или Client.write; отдельный MCP/ChatGPT-коннектор пока не установлен.

## Настройка в amoCRM

1. Войдите администратором именно в свой личный аккаунт. Проверьте адрес в браузере.
2. Откройте **амоМаркет → меню (три точки) → Создать интеграцию**.
   Расположение кнопки может зависеть от текущего интерфейса.
3. Если amoCRM предлагает соглашение об отказе от технической поддержки, прочитайте его
   перед принятием. Официальная документация предупреждает, что для приватной интеграции
   в нетехническом аккаунте отказ от приёма обращений по ошибкам системы необратим.
   Не принимайте его автоматически: это отдельное решение владельца аккаунта.
4. Название: **Личный AI — локальное чтение**.
   Описание: **Локальная интеграция на личном Mac для чтения данных через API.**
5. Redirect URI: **http://localhost:8765/callback**. Это значение для локального прототипа
   одного аккаунта. Если форма отклоняет localhost/http, не подставляйте чужой адрес:
   потребуется согласовать отдельный ваш HTTPS URI. Доступность этого URI в форме пока
   не подтверждена. Код берётся вручную из вкладки «Ключи», callback-сервер не нужен.
6. Выберите минимальный доступ к данным аккаунта, необходимый для чтения указанных сущностей.
   Не включайте уведомления, телефонию и прочие дополнительные доступы.
   OAuth-разрешение amoCRM может включать запись: режим чтения по умолчанию обеспечивается
   клиентом. Для записи используйте отдельные команды с --apply.
7. Если требуется иконка, загрузите своё изображение 400×272. Хук отключения оставьте пустым.
   Не загружайте виджет и не настраивайте автоматизации.
8. Сохраните интеграцию. Откройте вкладку **Ключи и доступы / Ключи**.
   Понадобятся ID интеграции, секретный ключ и код авторизации.

## Локальный ввод ключей

Откройте Terminal на Mac:

```sh
cd /Users/ilnarabdullin/Projects/developer/amocrm
python3 amo.py setup
```

Для адреса аккаунта нажмите Enter: по умолчанию используется https://infomedaccountru.amocrm.ru.
Введите ID, секрет и тот же Redirect URI, который сохранён в amoCRM.
Секрет вводится скрыто и не попадает в историю команд. Настройки сохраняются в `.env` с правами
`600`. `.env.example` содержит только шаблон. Не присылайте секреты или коды в чат.

Затем скопируйте свежий код авторизации из вкладки ключей интеграции и выполните:

```sh
python3 amo.py auth
```

Вставьте код в скрытый запрос ввода. Код действует 20 минут. Токены будут записаны в
`.private/tokens.json` (права `600`, каталог `700`). Не выводите этот файл в чат.
Повторная авторизация заменяет существующую пару токенов.

Если Terminal не принимает вставку в скрытое поле: сначала наберите (но не запускайте)
`python3 amo.py auth --from-clipboard`, затем скопируйте свежий код в amoCRM,
вернитесь в Terminal и нажмите Enter. Команда читает код из буфера Mac без вывода
на экран и без передачи в аргументах процесса. После авторизации скопируйте любой
несекретный текст, чтобы заменить код в буфере. Не копируйте саму команду после кода.

## Проверка чтения

```sh
python3 amo.py leads
python3 amo.py check
```

Первая команда показывает ID, название и основные поля первых 50 сделок.
Вторая читает первые страницы сделок, контактов, компаний и задач, все воронки и
статусы каждой найденной воронки. Выводит только количества и ID воронок.
Пустой список является успешным ответом, но не доказывает видимость всех данных аккаунта.

```sh
python3 amo.py contacts
python3 amo.py companies
python3 amo.py tasks --json
python3 amo.py pipelines
python3 amo.py statuses --pipeline 123
python3 amo.py leads --pages 3 --json
python3 amo.py refresh
```

`--pages` ограничивает число страниц (по 50 записей); по умолчанию одна.
`--json` выводит реальные данные CRM в stdout — это не журнал, не публикуйте этот вывод.
Команда `refresh` проверяет реальный обмен refresh token. После неё повторите `leads`.
Автоматическое обновление происходит при запросе за 60 секунд до истечения access token
или один раз после 401. Фоновый процесс не запускается.

## Защита и диагностика

- API v4: GET по белому списку; POST/PATCH для одной сделки, контакта, компании или задачи
  при явно включённой записи. DELETE и пакетная запись заблокированы.
- Токены сохраняются атомарно; файловая блокировка предотвращает одновременную ротацию
  несколькими локальными процессами. Новая пара сохраняется после каждого обмена.
- OAuth POST не повторяется автоматически при сетевой ошибке: одноразовый refresh мог
  уже быть использован сервером. Если последующее обновление не проходит, получите новый код.
- HTTP 401: обновление и одна повторная попытка; 403: проверьте права пользователя;
  400 при OAuth: проверьте код, ключи и точное совпадение Redirect URI.
- GET при 429/502/503/504 повторяется до двух раз с задержкой. Тайм-аут — 30 секунд.
- Логи содержат метод, путь без параметров и HTTP-статус. Тела ответов, заголовки,
  коды авторизации и токены в лог не включаются. Проверка TLS включена.
- HTTP-редиректы и системные прокси отключены, чтобы не передавать ключи другому хосту.
- `.env`, `.private`, виртуальное окружение и кэши исключены из git.
  Хранилище токенов локальное, с ограниченными правами, но не зашифровано приложением.
- Refresh token имеет ограниченный срок жизни; после длительного простоя может потребоваться auth.

## Создание и изменение с локального Mac

Интеграция остаётся на Mac. Codex в этом проекте использует `amo.py` как локальный
инструмент агента. Сервер и VPS не требуются. Команда выполняется только при работе
агента/CLI; фоновой работы 24/7 нет.

Подготовьте JSON в `.private/new-lead.json`:

```json
{"name": "Название сделки", "price": 0}
```

Сначала просмотр без запроса к CRM, затем выполнение:

```sh
python3 amo.py create --resource leads --data-file .private/new-lead.json
python3 amo.py create --resource leads --data-file .private/new-lead.json --apply
```

Для изменения создайте `.private/change.json` с нужными полями (без id):

```json
{"name": "Новое название"}
```

```sh
python3 amo.py update --resource leads --id 123 --data-file .private/change.json
python3 amo.py update --resource leads --id 123 --data-file .private/change.json --apply
```

Вместо `leads` доступны `contacts`, `companies`, `tasks`. Создание контакта/компании
требует `name`; задачи — `text` и `complete_till` (Unix timestamp). Для завершения задачи
используйте `is_completed: true` и `result: {"text": "Результат"}`. Для сделки поддержаны
`price`, `pipeline_id`, `status_id`, `responsible_user_id`, `custom_fields_values`.
Контакты поддерживают `first_name` и `last_name`, все CRM-карточки — custom_fields_values.
Неподдерживаемые поля отклоняются. Изменения воронок/статусов и удаление не реализованы.

Запись при сетевых ошибках, HTTP 429/5xx автоматически не повторяется: результат может
быть неизвестен. Сначала проверьте CRM, чтобы не создать дубликат. После HTTP 401 клиент
один раз обновляет токен и повторяет запрос. Логи содержат метод, путь, статус и ID,
но не поля, секреты или токены. Предварительный просмотр выводит переданные поля.

Проверка живой записи: `scripts/verify_write.py` создаёт одну тестовую сделку в статусе
143 с бюджетом 0, переименовывает и проверяет GET. Квитанция в `.private/write-test.json`
блокирует повторный запуск, включая ситуацию неопределённого результата создания.
Операции могут запускать настроенные в аккаунте автоматизации.

Живая проверка записи 23.09.2026 успешна: сделка ID 45550859 создана, переименована
и повторно прочитана. Статус 143 («Закрыто и не реализовано»), бюджет 0.
Создание/изменение контактов, компаний и задач проверено локально; живые записи этих
типов для теста не создавались.
