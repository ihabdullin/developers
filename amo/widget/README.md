# «Рекомендатель» — MVP для карточки сделки

Каталог является частью существующей личной интеграции amoCRM. Рабочая папка:
`/Users/ilnarabdullin/Projects/developer/amocrm`; публикация: `ihabdullin/developers`, каталог `amo/widget`.
Инфраструктура и ресурсы СПЕКТР не используются.

## Что делает

В правой панели сохранённой сделки появляется блок «Рекомендатель»:

1. Ввод от двух символов запускает `GET /api/v4/contacts?query=...` после паузы 450 мс.
2. Список показывает имя, телефон (если доступен), компанию (если доступна) и ID.
   Если API вернул только ID компании, её имя загружается отдельным GET и кешируется
   до закрытия карточки. По 10 контактов на страницу, кнопка «Показать ещё».
3. Только явный выбор контакта запускает запись. Даже единственный результат
   не выбирается автоматически. Пустой результат никогда не создаёт контакт.
4. Перед записью повторно читаются сделка и контакт, проверяется канал и отсутствие
   несохранённых изменений в полях канала/Contact ID. Затем один PATCH меняет только
   `Рекомендовал – Contact ID`; GET проверяет сохранённое значение.
5. Родное поле карточки синхронизируется через input/change, чтобы последующее обычное
   сохранение сделки не вернуло старый ID. Остальные поля и несохранённые правки не отправляются.
6. При повторном открытии contact_id читается из сделки, имя — из актуального контакта.
   Имя открывает `/contacts/detail/{contact_id}` в новой вкладке.

**Contact ID — единственный источник истины.** Текстовое поле ФИО не записывается и не
используется для восстановления связи. Выбор рекомендателя не привязывает его как
клиента сделки и не меняет связанный контакт покупателя.

Если поле канала существует, выбор разрешён только для настроенного enum рекомендации.
Если канала нет вообще, блок работает без фильтра по каналу. При другом канале блок
неактивен, сохранённый ID не очищается. После изменения канала штатно сохраните сделку
и нажмите «Обновить» в виджете. Для новой сделки сначала требуется её обычное сохранение.

## Проверенные поля личного аккаунта

Проверено через существующий OAuth-клиент и видимую форму карточки **24.09.2026**:

| Поле | ID | Тип / значение |
| --- | --- | --- |
| Рекомендовал – Contact ID | 1696677 | numeric, доступно в карточке |
| Канал привлечения | 1696671 | select |
| Значение рекомендации | 1617843 | **Рекомендации** (во множественном числе) |

Создавать поля в этом аккаунте не нужно. Поле имени на форме называется
«Кто привел - ФИО»; виджет его не меняет. Числовые ID не зашиты в исполняемый код:
при загрузке читаются все страницы `/api/v4/leads/custom_fields` и проверяются имена/типы.

Для повторной проверки из корня проекта:

```sh
python3 scripts/inspect_referrer_fields.py
```

Скрипт только читает метаданные, использует `amo.Client` и существующие `.env`/`.private`.
В `amo.py` добавлены только разрешённый GET метаданных полей и метод их полного чтения.
Запись структуры CRM по-прежнему заблокирована.

Если в другом состоянии аккаунта поля нет: сначала выполните эту проверку, затем
администратор проверяет список полей в настройках сделки, включая варианты тире/пробелов.
При действительно отсутствующем поле создайте **одно** поле типа «Число» с точным именем
«Рекомендовал – Contact ID», необязательное, доступное в карточке. Снова запустите проверку
и укажите полученный ID. Если поле существует, используйте его; не создавайте замену.
При дублях требуется выбрать конкретный ID в настройках. Виджет сам поля не создаёт,
не удаляет и не меняет типы. Существующее текстовое поле также поддерживается, если
оно хранит только положительный целый contact_id. Несовместимый тип блокирует выбор.

## Архитектура и безопасность

- Официальный WEB SDK: AMD `define(['jquery'])`, callbacks `render/init/bind_actions/destroy`,
  `render_template`, `get_settings`, `APP.isCard`, `APP.getBaseEntity`, `APP.data.current_card`.
- Подключение только `lcard-1` и `settings`, `init_once: false`.
- API вызывается через относительные URL на домене открытого аккаунта и его браузерную
  сессию, с правами текущего пользователя. Долгосрочных токенов, client secret, API keys,
  внешнего сервера, localStorage и копирования `.env` во frontend нет.
- `$authorizedAjax` предназначен для запросов на внешний сервер с временным токеном;
  здесь внешний сервер не нужен. Локальный Python OAuth и ротация остаются как были.
- Одна последовательная очередь запросов с паузой 300 мс; при 429 предлагается подождать.
  Автоматических повторов PATCH нет, неоднозначный результат проверяется чтением.
- Ответы устаревшего поиска не показываются, при закрытии прекращается очередь и
  снимаются обработчики. Данные контактов выводятся через `.text()`, без HTML-инъекций.
- Идемпотентность: выбранный уже сохранённый ID повторно не записывается. При конкурентном
  изменении другим пользователем проверяется свежий ID перед PATCH. API не предоставляет
  здесь атомарного compare-and-swap: крайне короткая гонка между GET и PATCH остаётся.
- Небольшой адаптер `src/card.js` синхронизирует родной input `CFV[field_id]`.
  Это DOM-зависимая часть, отдельно от WEB SDK. Разметка проверена в нашем аккаунте.
  При пропаже/неоднозначности/недоступности поля запись блокируется, обхода нет.
- При ошибке после PATCH нельзя считать запись неуспешной: нажмите «Обновить», при
  рассогласовании формы перезагрузите карточку после сохранения прочих правок.
- Удалённый/недоступный рекомендатель показывается как сохранённый ID с сообщением об ошибке;
  поле не очищается автоматически. Нет кнопки удаления и автоматического создания контакта.

## Сборка и проверки

Нужны Python 3.9+, Node.js 18+ и pnpm. Зависимости JS нужны только для тестов; в amoCRM
используется jQuery самого WEB SDK. В архив `node_modules` и тесты не входят.

```sh
# Из корня проекта
python3 -m unittest discover -s tests -v
cd widget
pnpm install --frozen-lockfile --ignore-scripts
python3 build.py
pnpm run lint
pnpm test
```

`lint` проверяет синтаксис через `node --check`; отдельного ESLint в проекте нет.
`build.py` собирает `src/` в один AMD `script.js`, проверяет manifest, переводы, PNG-размеры,
UTF-8 без BOM и составляет ZIP **по явному списку файлов**. Сборка детерминированная.
Логотипы воспроизводятся командой `python3 make_logos.py` (стандартная библиотека Python).

Результат: `widget/dist/referrer-1.0.0.zip` (исключён из Git). В корне архива:

```text
manifest.json
script.js
style.css
i18n/ru.json
images/logo.png
images/logo_main.png
images/logo_small.png
images/logo_medium.png
images/logo_min.png
```

Нет внешней папки `widget/`, секретов, исходников тестов или локальных данных.
Исходники и сгенерированный `script.js` коммитятся; ZIP воспроизводится сборкой.

## Установка в наш amoCRM

1. Соберите архив и войдите администратором в `https://infomedaccountru.amocrm.ru`.
2. Откройте **амоМаркет → Мои интеграции / созданные интеграции** и редактирование
   существующей личной интеграции. Подписи разделов могут меняться.
3. Включите загрузку виджета, если интерфейс показывает этот переключатель, и загрузите
   `widget/dist/referrer-1.0.0.zip` в поле архива виджета. Не заменяйте OAuth ID/secret,
   Redirect URI и существующие разрешения. Если нужных элементов нет, остановитесь
   и проверьте права/тип интеграции — не создавайте дублирующую интеграцию.
4. Сохраните новую версию интеграции, затем откройте настройки виджета и включите его.
   Локализация интеграции должна включать русский язык, как `locale: ["ru"]` в manifest.
5. Для нашего аккаунта можно оставить настройки пустыми (автопоиск уникальных имён),
   либо явно указать: Contact ID field `1696677`, channel field `1696671`, referral enum `1617843`.
   Никаких OAuth-данных или паролей в настройках виджета вводить не нужно.
6. Обновите страницу и откройте сохранённую сделку; разверните блок «Рекомендатель»
   в правой панели. Основная вкладка с полями Contact ID и канала должна быть доступна.

Установка не выполняется командой сборки. Загрузка в amoCRM и проверка в установленном
виджете — отдельный этап: локальные тесты не подтверждают принятие архива платформой.

## Приёмка после установки

Используйте уже созданные записи `[ТЕСТ API]`: сделка **45551485**, контакт **67221695**;
не создавайте повторно новые карточки. У сделки бюджет 0, закрытый неуспешный этап.

- Сохранить канал «Рекомендации», обновить виджет. Один символ не отправляет поиск;
  от двух показываются кандидаты. Несколько кандидатов требуют явного выбора.
- Найти тестовый контакт, выбрать; проверить Contact ID в родном поле и через API,
  закрыть/открыть сделку: имя восстановлено, ссылка ведёт к выбранному контакту.
- Проверить отсутствие совпадений, спецсимволы, быстрый ввод, другой канал, права чтения,
  отсутствие поля, удалённый ID. Телефон/компания показываются только когда доступны.
- Изменить другое поле сделки без сохранения, выбрать рекомендателя, затем штатно
  сохранить карточку: оба изменения остаются. Несохранённый канал/Contact ID блокирует выбор.
- Приёмочные изменения фиксировать на тестовой сделке; не запускать массовые сценарии.

## Разработка, обновление и откат

Редактируйте `src/`, а не собранный `script.js`. После правок увеличивайте версию
в manifest и package.json, собирайте ZIP, запускайте тесты и смотрите diff. Загрузите
новый архив в ту же интеграцию и обновите вкладки пользователей. При проблемах отключите
виджет или загрузите предыдущий проверенный архив; значения Contact ID сохраняются.

На 24.09.2026 локальный Git и Git репозитория `developers` имеют разные корни:
в локальном проекте файлы лежат в корне, на GitHub — внутри `amo/`. Для push используйте
рабочую копию `developers`, синхронизируя только `amo/` по списку версионируемых файлов.
Не делайте обычный push локального корня поверх корня `developers`; не копируйте `.git`,
`.env`, `.private`, node_modules и dist. Сохраняйте остальное содержимое developers.
